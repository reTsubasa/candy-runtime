Status: partial implementation and measured failures retained. No production

## P0 Changes

Core `11648c4` removes legacy Ready/CommitAck without an actor proof and rejects
ordinary outbound replacement before OPEN can evict a valid remote lane.
An ordinary Prepare returns a tuple-bound rejection while its transport stays
usable and its fencing floor is unchanged. Actor-backed candidate replies have
a two-second bound and the original authorization cap; uncertain delivery keeps
the original controller/receipt. Version 2 authorization bindings include the
actor process incarnation, preventing reuse of numeric connection/owner IDs
after restart. Coordinator Abort diagnostics validate the tuple and retain the
remote reason. This is containment, not full make-before-break.

Runtime `cbd5d75` no longer treats malformed, unsafe or unreadable process proof
as absence. Only NotFound permits an optional record. Other read errors and
unknown shared-worker liveness return ManagedProofPending with the original
cause, preserving the journal/owner for existing bounded recovery. This also
applies before archiving a retired IO transaction.

Recovery disposition now reads both process records before selecting renewal or
pair recovery; a corrupt worker record cannot be bypassed by the IO fast path.
SD-WAN liveness checks use a fallible procfs probe. Only confirmed exit or epoch
change returns false; permission, IO or malformed procfs data retains a typed
`process_liveness_unconfirmed` cause and the original ownership. Renewal/rebind
cleanup preserves the candidate and infrastructure on that uncertainty.

A regression test exposed a further retry bug: typed values added with
`anyhow::Context` were not recognized by scanning `std::error::Error::source`.
Runtime now uses anyhow's typed downcast for all recovery markers, preserving
bounded retries for nested proof/Core/pair/netd/desired-state context. Invalid
signed policy still waits for corrected inputs. Uncertain commit errors retain
the original detailed cause rather than replacing it with an empty marker.

Runtime `3142398`, `d2ee3e8` and `78464ab` extend this containment to recovery
input fingerprints, shared-pool/listener registration, and hot-reload binding
verification. A read or liveness error now rolls back only an uncommitted
candidate, retains the active owner/TUN path, or enters bounded retry after a
commit. It cannot be converted into a false "unchanged" or "dead" result.

Core `f441013` and `6dac801` isolate Proxy worker dispatch failures. A worker
lease is released when a concurrent retirement wins the race; transient private
socket accept errors retry without killing the worker; and a saturated worker
returns an immediate bounded rejection instead of leaving the master waiting for
the dispatch timeout. Existing Proxy and SD-WAN owners remain charged and
healthy roles continue independently.
